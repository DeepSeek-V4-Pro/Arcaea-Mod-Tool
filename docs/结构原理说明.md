## 总体架构

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 前端 | `webui/`（Vue 3 + Vite） | 组件树（浏览 / 替换 / 构建 / 配置 / 实验控制台）、`store.js` 响应式状态 |
| 后端 | `app/`（FastAPI） | `routes/` 按业务域划分（assets / patches / build / packs / config / **lab**）、`state.py` 进程状态、`deps.py` 共享依赖 |
| 引擎 | `core/`（纯逻辑） | `zipio` zip 解析与原始字节重打包、`catalog` 目录与分类、`patches` 补丁存储与图片处理、`builder` 构建流水线、`signing` APK v2 签名、**`iosmode` iOS 原包定位** |

**调用方向**：`webui/ ──HTTP──► app/ ──► core/`

**分层约定**：`core/` 是纯逻辑引擎（不依赖 FastAPI，可独立测试）；`app/` 负责 HTTP 与进程状态；`webui/` 是 Vue 3 前端，构建产物由后端 `/static` 挂载。

**数据流**：`扫描 → 目录缓存 → 浏览 / 替换（写入补丁 blob）→ 构建（重打包 + 签名 + 校验）→ 产物`

## 原包读取逻辑

> 模块：`core/zipio.py`

APK 即 zip 档案。**不解压、不整包读取**，只解析中央目录 + 按需 seek：

1. **定位 EOCD**：文件尾部反向扫描 `PK\x05\x06`（最多回扫 65557 字节）
2. **读中央目录**：从 EOCD 的 `cd_offset` / `cd_size` 一次性读入整个中央目录（约几百 KB），逐条解析 46 字节目录头 + 文件名 + `extra` + 注释；`extra` 中的 zip64 字段（`0x0001`）覆盖压缩 / 原始大小与本地头偏移
3. **回读本地头**：每条目再读一次本地头（30 字节）取真实的 `fn` / `extra` 长度——**本地 extra 与中央目录 extra 可能不一致，必须以本地头为准**才能正确定位数据区（官方打包工具常见差异，最易踩的坑）
4. **缓存**：解析结果按 `(路径, mtime, 大小)` 缓存。浏览 / 缩略图会发起大量逐条读取，全量解析 7000+ 条目录很贵，缓存后接近零开销

**按需读数据** `read_entry_data()`：`seek(本地头偏移 + 30 + fn_len + extra_len)` → 读 `csize` 字节 → stored 直接返回；deflate 用 `zlib.decompress(raw, -15)`（raw deflate 无 zip 头）。

**zip64 兜底**：EOCD 字段为 `0xFFFFFFFF` 时经 locator 找 zip64 EOCD；1.8 GB 在 zip32 范围内，但解析器完整支持 zip64 防未来大包。

**性能**：全量目录解析 <1 秒；批量导出按 `header_offset` 排序后单次顺序读，5760 张 1.13 GB 实测约 7 秒。

## 重打包

> 模块：`core/zipio.py` 的 `build_apk`

**核心思想：原始字节级拷贝，只重压缩被替换的条目。**

- 遍历计划：原条目（未替换）→ 从源文件按 `local_record_size` 原样拷贝数据区；替换 / 新增条目 → 重新压缩
- `STORE_EXTS`（png/jpg/ogg/mp3 等已压缩格式）与 <64 字节数据直接存储（stored），避免无谓压缩
- **数据描述符消除**：重写本地头时清掉 `flag bit 3`，本地头直接携带 crc / size（无描述符的「干净」zip）
- **4 字节对齐**：stored 条目在 extra 补 padding，使数据区起始 4 字节对齐（zipalign 风格，Android 可 mmap 优化）
- 中央目录与 EOCD 全新重建，偏移精确
- 输出永远是干净的 zip32；未替换条目保持原压缩数据，所以速度只受被替换条目影响

## 签名

> 模块：`core/signing.py`，纯 Python APK v2

**算法**：`0x0103 = RSASSA-PKCS1-v1_5 with SHA-256`（注意：`0x0101` / `0x0102` 是 PSS，勿混用——这是设备校验失败「缺少开发者证书」的经典根因）。

**内容摘要**（AOSP chunked digest，与官方 apksig 完全一致）：

```text
每块(1 MiB)摘要 = SHA-256(0xa5 ‖ 块长(uint32 LE) ‖ 块内容)
最终摘要        = SHA-256(0x5a ‖ 块数(uint32 LE) ‖ 各块摘要按序拼接)
```

摘要覆盖 `[0..签名块起点) + [中央目录..EOCD) + EOCD(cd_offset 改写为签名块起点)`。

**签名块结构**：`size1 ‖ pairs ‖ size2 ‖ "APK Sig Block 42"`，pair = `uint64(len+4) ‖ uint32 ID(0x7109871A) ‖ value`；value = 签名者序列（signed data：digests ‖ certs ‖ attrs；signatures；public key）。

**EOCD 约定**：签名后 EOCD 的 `cd_offset` 指向**签名块之后的中央目录**（与官方 APK 实测一致——原版 `arcaea_6.16.2c.apk` 即此布局）。

**验证链**（构建后自动执行三道）：

1. 本地 `verify_apk`（摘要 + RSA 签名）
2. `apksigtool` 独立实现交叉验证（其 HASHERS 仅支持 `0x0103` / `0x0104`）
3. 官方 `apksig` jar（与设备相同的校验逻辑）——开发期用 Java 验证，金标准：对原版 APK 用本实现重算摘要，与官方签名块内存储值逐字节比对

**密钥**：`data/keystore/`（`modkey.pem` + `modcert.pem`），首次自动生成 RSA-2048 自签名证书（30 年），复用不重建。**更换密钥后旧 mod 无法再安装**。

> **开发期踩坑记录**（已修复并有测试兜底）：
> 1. 算法 ID 误用 `0x0101`（PSS）→ 设备按 `0x0103` 找不到 PKCS1 签名 → 「缺少开发者证书」
> 2. 顶层摘要块数写死 1 且预哈希 → 与设备计算的摘要不匹配；正确做法是 `0x5a ‖ 真实块数 ‖ 块摘要拼接`

## 图片处理管线

> 模块：`core/patches.py`

上传 / 预览时统一走 `PatchStore.process_image(data, orig_ext, settings)`，按设置依次执行：

```text
解码 → 模式转换(RGBA/RGB) → [fit_zone 半身裁切] → [fit 比例裁切] → [keep_size / scale 缩放]
     → [shape=diamond 菱形蒙版] → [底部淡出] → 编码(PNG/JPG)
```

**设置项**（`settings_json`，前端实时预览）：

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `fit` | `"crop"` | 自动裁切校准：按原素材宽高比裁切后缩放到原素材精确尺寸 |
| `fit_align` | `center` / `top` / `bottom` | 裁切保留位置（top 适合立绘头像保留头部） |
| `fit_zone` | `0 < z < 1` | 联机立绘半身裁切：先保留源图顶部 z（默认 0.55），再适配 |
| `keep_size` | bool | 拉伸到原素材尺寸（不校正比例） |
| `scale` | 1–400 | 百分比缩放 |
| `fmt` | png / jpg | 输出格式；JPG 透明合成白底 |
| `quality` | 1–100 | JPG 质量 |
| `shape` | diamond / none | 菱形蒙版（路由层按路径自动识别头像） |
| `orig_w` / `orig_h` | 像素 | 原素材真实尺寸，由路由层从 APK 读取并缓存 |

**菱形蒙版**：逐像素解析判定内切菱形 `|2x-(w-1)|/w + |2y-(h-1)|/h ≤ 1`（顶点在四边中点）。官方头像实测：正方形画布（约 170×170）+ 四角 alpha=0、不透明占比 ≈0.50——菱形是素材自带镂空，直接替换实心图会穿帮，故自动蒙版。不用多边形光栅化是因为顶点像素会被裁掉（官方顶点带过渡）。

**联机立绘半身裁切**：`*_mp.png` 实测为原立绘（`char/1080/<id>.png`，1800×1800）**顶部约 55% 的放大**（像素拟合最佳值 0.55），且截断处为渐变透明：官方 alpha 曲线 70% → 88% 线性淡出到 0。实现：先裁顶部 55% → 比例适配 → 底部 25% 做 1 → 0 线性 alpha 渐变（列向量拉伸实现，C 级速度）。

## 前端结构

> 目录：`webui/src`

```text
webui/src/
├── main.js / App.vue          挂载入口 / 页面外壳（解包 | 替换 | 实验 + 配置弹窗）
├── store.js                   全局响应式状态（catalog / patches / buildJob / exportSel / page）
├── api.js / toast.js / utils  请求封装 / 全局提示 / 工具函数
├── pages/
│   ├── ExtractPage.vue        解包页：Sidebar + AssetGrid + DetailPanel
│   ├── ReplacePage.vue        替换页：PatchList + PatchDetail + BuildPanel
│   └── LabPage.vue            实验页：平台切换 + 原包状态 + input/ 候选清单
└── components/
    ├── VSelect.vue            自定义下拉组件（排序 / 每页 / 裁切位置 / 输出格式）
    ├── AssetCard.vue          素材卡片（勾选导出 / 拖放替换 / 已替换徽章）
    ├── AssetGrid.vue          工具栏（导出 / 排序 / 分页 / 全选）+ 网格
    ├── DetailPanel.vue        详情 + 图片处理对话框（三栏预览 + 选项）
    ├── PatchList.vue          替换清单（启用 / 停用）
    ├── PatchDetail.vue        补丁详情（原素材 vs 替换内容）
    ├── BuildPanel.vue         构建面板（进度 / 日志 / 下载）
    ├── Sidebar.vue            分类侧边栏
    ├── AppHeader.vue          页头
    ├── ConfigDialog.vue       配置弹窗
    ├── Dropzone.vue           拖拽上传区
    └── ToastHost.vue          全局提示
```

**VSelect 设计要点**：原生 `<select>` 隐藏仅作数据源（label 语义保留），自绘弹层接管交互（悬停高亮 / ✓ 选中 / 方向键 / Esc / 点击外部关闭）。弹层必须 `<Teleport to="body">`——面板上的 `backdrop-filter` 会把 `position:fixed` 的包含块从视口变成面板容器，导致弹层位置叠加面板偏移（实测 800px 宽窗口偏移约 200px）。另外 `<label>` 包裹时浏览器会把点击重派发给隐藏 select，需在触发器忽略该合成点击。

**响应式断点**：1440 / 1180 / 960 / 720 / 矮屏 760；≤960px 侧边栏变横向分类条、面板堆叠。

## 开发指南

```bat
:: 后端（热改需重启）
.venv\Scripts\python -m app

:: 前端开发模式（热更新，代理到 8000）
cd webui && npm run dev        :: http://localhost:5173

:: 前端构建
cd webui && npm run build

:: 语法检查（纯 AST，不落盘，可绕过服务锁定的 pycache）
.venv\Scripts\python -c "import ast,pathlib;[ast.parse(p.read_text(encoding='utf-8'),filename=str(p)) for p in [*pathlib.Path('app').rglob('*.py'),*pathlib.Path('core').rglob('*.py')] if '__pycache__' not in str(p)]"
```

**验证体系**：图片处理（几何 / 淡出曲线 / 字节级一致性）、签名（本地 + apksigtool + 官方 apksig 三方）、分类规则（抽样路径断言）均有可复跑的验证脚本思路；批注参见各模块 docstring。iOS 模式另有 `scripts/selftest/`（合成 IPA 全链路 22 项断言 + input/ 识别组合 19 项断言 + 真实 940MB 包链路 3 项校验，共 44 项）。

**iOS 实验模式设计**（`core/iosmode.py` + `app/routes/lab.py` + 「实验」页）：

- **定位**：IPA 即 zip；`iosmode.detect_app_root()` 从中央目录探测 `Payload/<App>.app/` 前缀，作为 iOS 素材根
- **复用**：`build_catalog(pkg_path, asset_root)` 剥离根前缀后走既有分类规则（两平台同构）；补丁键始终是 zip 全路径，构建无需转换
- **原包**：`iosmode.resolve_ipa()` 支持外层 zip（暗改包分发格式），自动解出内层 IPA 到 `data/ipa_cache/`（按 路径+mtime+大小 缓存）；官方 App Store 包带 FairPlay DRM，`need_apk` 对 iOS 校验 `Payload/<App>.app/` 存在性
- **构建**：`builder._run_build_ios()` 只做 重打包（`drop_prefixes` 移除 `_CodeSignature/`）→ 结构校验（替换条目存在且大小一致），**不签名**——iOS 无离线自签，产物由用户用 Sideloadly / 爱思助手签名
- **平台切换**：`POST /api/lab/platform` 写 `settings.platform` 并作废目录缓存；头像菱形蒙版 / 联机立绘半身裁切的路径正则改为兼容两平台全路径形态

**约定**：

- `core/` 不依赖 FastAPI；所有路径基于项目根推导；`input/` 原包统一自动识别（`*.apk` / `*.ipa` / 外层 `*.zip`，取最大候选，配置路径优先、按文件类型判定平台）
- 修改 API 请同步更新本文件与 README
